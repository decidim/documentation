= Representações dos usuários

Para participantes que não possuem conhecimento ou não possuem um e-mail para registrar uma conta
de personificação, existe o recurso de representação.

Isso permite que um 'Administrador' ou 'Gerenciador de Participantes' pesquise por meio de um sistema de verificação
para um usuário já existente e também crie um participante
sem e-mail.

NOTE: No código e na interface do usuário, dizemos *Representação* e *Gerenciados
Participantes*. É a mesma coisa.

== Painel

image::participants_impersonations.png[Admin's Impersonations panel]

Este é o painel onde você pode encontrar todos os participantes:

* filtragem por participantes gerenciados ou não gerenciados
* ao pesquisar por nome

Depois de clicar em `Gerenciar novos participantes` você vai ao formulário para inserir
os dados pessoais para checar contra a verificação:

image::participants_impersonations_form.png[Admin's Impersonations form]

NOTE: Se você não vir o botão `Gerenciar novo participante`, é porque esse recurso
só funciona quando você tem um tipo de Verificação `direct` (também conhecido
como `form authorizations`). Veja no seu xref:admin: system.adoc[painel do sistema] que
`Autorizações disponíveis` estão ativadas. Você pode aprender mais sobre como programar
sua autorização do formulário em https://github.com/decidim/decidim/blob/develop/decidim-verifications/README.md[decidim-verification README].

Depois que esses dados forem confirmados, haverá uma sessão para o participante por
30 minutos:

image::participants_impersonations_user.png[Impersonated user session]

Finally, it's also possible to Promote a participant, meaning that after a
participant has been managed, an administrator can add the email and send her
an Invitation:

image::participants_impersonations_promotion.png[Admin's promotion Impersonations]
